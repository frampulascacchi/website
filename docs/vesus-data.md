# Fetching Vesus.org data

Reference for pulling tournament data (event list, shortKeys, standings, venue, regulation) from [vesus.org](https://vesus.org).

## Why not just fetch the pages

Vesus is a GraphQL SPA served from S3/CloudFront. Direct HTTP requests to `/user/...`, `/tournament/...`, etc. return **status 404 with the SPA shell as the body** (S3 `NoSuchKey`), so `webfetch`/`curl` report failure even though browsers render the page fine. Use the GraphQL API instead, or a headless browser as a fallback.

## GraphQL API basics

- Endpoint: `POST https://api.vesus.org/graphql`
- Required headers:
  - `Content-Type: application/json`
  - `Origin: https://vesus.org` (without it the API returns `500 Invalid origin`)
- Persisted queries only. Request body is:

  ```json
  {"docId":"<32-hex-id>","operationName":"<Name>","variables":{...}}
  ```

  Sending a `query` body returns `PersistedQueryOnly`.

## Known persisted queries

The club account is `frampulascacchi`.

### List the club's tournaments

```bash
curl -s -X POST -H "Content-Type: application/json" -H "Origin: https://vesus.org" \
  -d '{"docId":"30126cc9b73b521cef13aaeae83f0a85","operationName":"UserEventsCreatorQuery","variables":{"username":"frampulascacchi","count":100,"cursor":null}}' \
  https://api.vesus.org/graphql > events.json
```

Each edge has `node.name`, `node.start`, and `node.tournaments[0].shortKey` (the key used in `https://vesus.org/tournament/<shortKey>`).

### Standings + full tournament details

`TournamentPage_Subscription` is an SSE subscription that never closes, so cap it with `--max-time`:

```bash
curl -s -N --max-time 12 -H "Content-Type: application/json" -H "Accept: text/event-stream" \
  -H "Origin: https://vesus.org" \
  -d '{"docId":"2b7be2c69372d525856bc40916204211","operationName":"TournamentPage_Subscription","variables":{"shortKey":"<SHORT_KEY>","hasCompletedPublishedRounds":true,"hasGames":false,"hasResults":true,"canNoLongerBeUpdated":true}}' \
  https://api.vesus.org/graphql > sub.txt
```

Parse the first `data: ` line as JSON. `data.tournamentUpdate` contains:

- `players`: `rank`, `title`, `name`, `points`, `performanceRating`, `tieBreaks` (values are ordered like `playersTieBreaks`)
- `playersTieBreaks`: e.g. `["BH/P","ARO","APRO"]` or `["DE/P","BH/P","ARO"]`
- `event`: `venue`, `regulation` (PDF uuid), `organiser`, `contactsEmail`, `contactsPhone`, `location`
- `timeControl.periods[0].white/black`: `minutes` / `increment`
- `pairings`: rounds/results
- `tournamentFile`: uuid of the `.vct` file

### Authoritative time control

The regulation PDF can be stale. The `.vct` file (`https://vesus.org/assets/tournamentFiles/<tournamentFile>.vct`) is a JSON snapshot generated by the tournament handler and reflects the time control actually used:

```bash
curl -s -o tf.vct "https://vesus.org/assets/tournamentFiles/<tournamentFile>.vct"
python3 -c "import json;d=json.load(open('tf.vct'));print(d['timeControl'],d['rounds'],d['playersTieBreaks'])"
```

## Regulation PDFs

`event.regulation` maps to `https://vesus.org/assets/regulations/<uuid>.pdf`. Extract text and hyperlinks (maps link, WhatsApp pre-registration link, contacts) with `pypdf`:

```bash
python3 -m pip install --quiet --target /tmp/pylibs pypdf
PYTHONPATH=/tmp/pylibs python3 - <<'EOF'
from pypdf import PdfReader
r = PdfReader('reg.pdf')
print('\n'.join(p.extract_text() or '' for p in r.pages))
for p in r.pages:
    for a in (p.get('/Annots') or []):
        uri = (a.get_object().get('/A') or {}).get('/URI')
        if uri:
            print(uri)
EOF
```

## Re-extracting persisted query ids

When Vesus deploys, the bundle hash changes. Get the script tag from `https://vesus.org/`, download `https://vesus.org/static/js/index-<hash>.js`, then grep:

```bash
rg -o 'params:\{id:"[^"]+",metadata:\{[^}]*\},name:"[^"]+",operationKind:"[^"]+",text:null\}' index-*.js
```

Page-specific queries live in lazy chunks too (e.g. the user page chunk imports `UserPage_Query` from the main bundle); search the main bundle and the chunk imports.

## Headless browser fallback

Chrome renders the SPA even though HTTP clients get the 404 shell. The SSE connection keeps pages "loading", so run it with a kill timeout:

```bash
("/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --no-first-run --user-data-dir=/tmp/chrome-vesus --virtual-time-budget=35000 \
  --dump-dom "URL" > dom.html 2>/dev/null & CPID=$!; sleep 50; kill $CPID 2>/dev/null)
```

Strip tags with `python3` + regex to read the text. Useful URLs:

- `?selectedTab=tournament.details` — venue, dates, registrations, time control
- `/tournament/<shortKey>/pairings` — standings table (Pos, Num, Name, Fed, Rtg, Rtg.P., Pts, tiebreaks)

## Building the site's classifica tables

`scripts/convert_vesus_standing.py` converts a Vesus standings txt export (columns `DE | BH | BH/C1 | ARO`) into the Markdown table used on the site. Without that export, build the table from the subscription `players` array: `Pos | Name | Perf | Pts | <tiebreaks>` with `playersTieBreaks` as the tie-break columns, prefixing `title` to the name and bolding the top 3 (see existing pages in `content/tornei/`).

## Automated calendar sync

`scripts/sync_vesus.py` uses `UserEventsCreatorQuery` to rewrite the upcoming/past lists in `content/tornei/_index.md`:

- upcoming tournaments are listed with their vesus registration link;
- played tournaments (`end` in the past, Europe/Rome) move to the past list, linking the local page when a page in `content/tornei/` contains the matching shortKey, otherwise linking vesus.org;
- existing entry labels are preserved, so manually curated names are kept; entries whose event disappeared from vesus stay in the archive.

Run it manually with `python3 scripts/sync_vesus.py` (or `--dry-run` to print the result). `.github/workflows/sync-vesus.yml` runs it daily and commits changes to `main`, which triggers the normal deploy workflow.
